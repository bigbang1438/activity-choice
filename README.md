# 一起定活动

Java 全栈个人作品：几位朋友比较活动候选、各自表达偏好，由组织者确认主选、备选和集合信息，再生成可撤销的只读定案。

它解决的具体问题是：群聊中的费用/预约信息容易缺失或过期，改票后汇总不清，公开整个讨论又可能带出未选方案和成员备注。因此候选使用结构化规则和来源，偏好可以改选撤回，公开页只读取发布时冻结的白名单副本。

这是**本机单进程作品**，没有真实用户或商业收益数据。匿名分享只代表同一台电脑上无需登录阅读，没有公网上线；它不能订票、支付、自动核实来源或保证所有朋友已达成共识。

## 快速运行

需要 JDK 21、Maven 3.8+。仓库已含当前静态构建页面，首次启动不必先安装前端依赖。在仓库根目录执行：

```powershell
cd server
mvn test
mvn package
java -jar target/activity-choice-1.0.0.jar
```

打开 `http://127.0.0.1:8098/`。默认数据库写入后端工作目录的 `data/activity-choice`，不要同时启动两个实例使用同一数据文件。账号和活动保存在本机；会话不跨服务重启保留，重启后重新登录。

需要修改前端时，使用 Node.js 24，在 `web` 目录执行 `npm ci`、`npm test`、`npm run build`，再将 `web/dist` 内容复制到 `server/src/main/resources/static` 并重新 `mvn package`。不要只改源码却继续运行旧构建。详细说明见 [后端 README](server/README.md) 与 [前端 README](web/README.md)。

## 完整流程

1. 创建自己的账号：用户名 3—32 位字母、数字或下划线，密码 8—128 个字符。没有固定演示账号。
2. 新建活动，录入至少两个候选，分别写地点、时段、开放、费用、预约。不了解的规则保持“尚未核实”；已核实项必须有文字、来源和日期，系统不替用户验证网页事实。
3. 组织者生成一次性邀请。朋友用自己的独立浏览器会话注册登录，粘贴邀请链接或邀请码领取。过期、撤销、已经领取的邀请不能再加入。
4. 各成员在每个候选选择“想去 / 可接受 / 不想去”，可以改选撤回，并查看谁还未回应。点击“刷新回应”读取新数据。
5. 组织者保存不同的主备方案及集合信息。若有人刚改了候选或偏好，旧版本保存被拒绝，刷新后需重新确认。
6. 发布只读链接。它不含成员、偏好、未选候选或成员备注；后续修改不改写旧版。新发布后旧链接标明旧版，撤销后原链接不再读取正文。

## 实际验证与局限

后端 15 项测试、前端 6 项逻辑测试通过；另有三账号独立 API 验收、隔离浏览器会话和 375 px 只读页检查。测试账号和任务不是实际用户试用。详见 [EVIDENCE.md](EVIDENCE.md)、[源码与后端回归说明](server/backend-evidence.md)。

没有账号找回、成员移除/退出、候选删除、容量配额、备份、多实例运行或生产负载验证。按账号计唯一偏好不等于实名制；同一自然人可能注册多个账号。HTTP/Cookie 与本机 Host/Origin 约束按本机环境设计，不能直接改成公网部署并声称安全。

公开仓库仅包含源码、测试、锁文件、当前静态页面和实施说明；不含个人简历、照片、资料库、数据库、模型、原始第三方 PDF、运行截图或验收账号数据。原开发环境的外部 QA/研究材料未随源码提交，相关摘要统一见 EVIDENCE.md。
